Critical — ต้องแก้ก่อน
C-1: Anon key hardcode ใน lib/supabase.ts
ควรลบ fallback key ออก บังคับใช้ env var อย่างเดียว

C-2: bootstrap() สร้าง profile ผ่าน anon client
ถ้า RLS INSERT policy เปิดกว้างเกินไป ผู้ใช้ใหม่สามารถ upsert role: 'admin' ตัวเองได้โดยตรง ควรให้ trigger ฝั่ง DB จัดการเท่านั้น

C-3: runRecall() ไม่มี transaction
UPDATE leads สำเร็จ แต่ถ้า insert activity log บางตัว fail — leads ถูก recall ไปแล้วแต่ไม่มี audit trail ควรย้ายไปเป็น server RPC

C-4: deleteRow(table, id) รับ table name เป็น string ไม่มี type constraint
ควร narrow เป็น union type ของ table ที่อนุญาตเท่านั้น

H-7	checkReminders() เรียก loadCrmData() (9 queries) ทุกครั้ง per reminder ที่ครบกำหนด

ขั้นตอนที่เหลือมีแค่นี้:

1. เอา secret key จาก database

รัน SQL นี้ใน Supabase SQL editor:


SELECT webhook_secret FROM website_settings LIMIT 1;
เอาค่าที่ได้ไปใส่ข้อ 2

2. อัปเดต .env.local บน Website

ไปที่ asakan-website/.env.local แล้วแก้ 2 บรรทัดสุดท้าย:


CRM_WEBHOOK_URL=http://localhost:3000/api/leads/from-website
CRM_WEBHOOK_SECRET=<ค่า webhook_secret จากข้อ 1>
(ถ้า CRM deploy อยู่บน domain จริง ให้ใส่ URL นั้นแทน)

3. Restart dev server ทั้งสองฝั่ง (ถ้ารัน local)

4. ตั้งกฎ mapping ใน CRM

ไปที่ CRM → คลิก gear ⚙️ → Website Leads → เพิ่มกฎ:

Project Slug	Pipeline	ขั้นตอน	ผู้รับ
asakan-korat	...	...	...
slug ต้องตรงกับค่า project ที่ form ส่งมา — ดูได้จาก form บน website ว่า field project ส่งค่าอะไร

5. ทดสอบ

กรอก form บน website แล้วดูว่าลีดขึ้นใน CRM หรือไม่ หรือจะทดสอบตรงๆ ด้วย:


curl -X POST http://localhost:3000/api/leads/from-website \
  -H "Content-Type: application/json" \
  -d '{"secret":"<your-secret>","project_slug":"asakan-korat","name":"ทดสอบ","phone":"0812345678"}'
